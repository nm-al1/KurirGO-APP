# GPS Android dan demo lokal

Build operasional: `flutter build apk --debug --flavor production`.

Build demo: `flutter build apk --debug --flavor demo --dart-define=DEMO_MODE=true`.

Demo memakai application ID `com.browcyl.kurir_go.demo`, database `courier_demo.db`, profil Kurir Demo / demo. Aplikasi langsung membuka Home tanpa akun server. Ada 6 pesanan antrean pada 5 lokasi dan 14 riwayat contoh selama 7 hari. Seed hanya sekali, bertahan setelah restart, dan dapat dikembalikan lewat Profil → Reset data demo. Kontak contoh tidak dapat ditelepon atau dikirim WhatsApp. Data demo tidak membuat operasi sinkronisasi Supabase.

Untuk demo offline, pilih seluruh enam pesanan bawaan yang koordinatnya belum diubah. `assets/routes/demo_loop.json` menyimpan matriks jarak jalan OSRM, urutan Held–Karp dan geometry untuk lima tujuan serta kembali ke depot. Algoritma yang sama digunakan untuk pesanan online; runtime memeriksa bahwa urutan fixture sesuai solver. Jalankan `dart run bin/refresh_demo_route.dart` untuk memperbarui fixture. Tes brute force terhadap seluruh 120 urutan membuktikan total minimum pada matriks tersimpan. Pilihan/data berbeda memakai perhitungan jalan online biasa. Peta dasar tetap membutuhkan internet. Perjalanan yang sudah dimulai mempertahankan urutan lamanya; susun perjalanan baru atau gunakan reset demo untuk memeriksa fixture baru.

Perjalanan demo memakai simulasi; tombol Gunakan GPS HP mengaktifkan GPS Android nyata. Build operasional memakai GPS pada halaman pengantaran. Izin lokasi diminta saat GPS mulai, dengan tindakan pengaturan untuk izin ditolak atau GPS mati. Android foreground service menjaga subscription ketika berpindah halaman/aplikasi atau layar terkunci. Notifikasi menandai pengantaran aktif. Hentikan GPS memutus subscription; aktifkan lagi untuk melanjutkan. Setoran, logout dan reset demo menghentikan tracking. Force-stop/proses dibunuh sistem tidak dijanjikan tetap berjalan; buka kembali perjalanan untuk memperoleh posisi baru.

Lokasi hanya berada dalam memori pengendali navigasi; tidak dikirim sebagai jejak koordinat ke Supabase. Geometry hitung ulang disimpan pada cache lokal terpisah dari snapshot perjalanan server. Data cache geometry mengandung titik awal hitung ulang dan harus diperlakukan sebagai data lokasi lokal.

Posisi >15 detik atau akurasi >50 meter ditandai lemah. Posisi tetap ditampilkan beserta akurasi tetapi tidak dipakai memperbarui kemajuan atau memicu hitung ulang. Dua posisi layak di radius 50 meter menandai mendekati tujuan; penyelesaian pengantaran dan pembayaran tetap manual. Posisi layak pertama yang jauh dari ruas langsung meminta jalan penghubung, termasuk ketika HP diam. Penyimpangan berikutnya membutuhkan tiga posisi layak >50 meter dari ruas. Satu permintaan berjalan dan jeda minimum 30 detik; respons tujuan lama diabaikan. Kegagalan jaringan menampilkan peringatan tanpa garis lurus pengganti.

Perbaikan tampilan GPS: seluruh ruas tetap digambar, dengan ruas aktif lime dan sisanya slate. Geometry hitung ulang hanya mengganti ruas aktif. Kamera menampilkan gambaran rute ketika posisi belum layak atau posisi awal jauh, lalu mengikuti GPS sesudah jalan penghubung tersedia. Tombol Lihat seluruh rute menghentikan follow; Kunci posisi kurir mengaktifkannya lagi. Pergantian mode, kegagalan routing, dan GPS berhenti tidak menghapus rute tersimpan.

Validasi perbaikan rute: 83 tes Flutter lulus, termasuk kesesuaian Held–Karp dengan seluruh 120 permutasi fixture, permintaan penghubung pada posisi pertama yang diam dan jauh, geometry dipertahankan ketika layanan gagal, serta pergantian simulasi ke GPS sebelum fix dengan seluruh ruas dan kontrol overview tetap tersedia. Fixture baru memiliki biaya matriks 46.496,7 meter, dibanding 49.133,9 meter untuk urutan manual lama pada matriks yang sama. Urutan baru: depot → Mamajang → Losari → Rappocini → Sudiang → Antang → depot. Ini optimal pada matriks tersimpan; jarak geometry bisa berbeda karena respons route dan pembatasan belokan jalan.

Gate visual pada lingkup perbaikan: PASS untuk jumlah/warna ruas dan kontrol overview melalui widget test; PASS untuk mempertahankan identitas lime/slate yang sudah ada tanpa perubahan layout utama. Pembacaan GPS langsung dan perilaku kamera selama perjalanan fisik belum diuji ulang pada tahap ini; hasil unit/widget tidak menggantikannya.

Pengujian otomatis mencakup kualitas/urutan posisi, proyeksi jalan, kedatangan, penghentian tracking, subscription tunggal dan respons hitung ulang terlambat. Demo diperiksa untuk seed, jumlah data, pin bersama, reset, isolasi akun serta tidak adanya outbox server.

Hasil 16 November 2026: seluruh 80 tes lulus, analyzer bersih. Setelah penambahan pemeriksaan akurasi invalid dan batas pencarian segmen maju, tiga tes GPS kembali lulus. APK demo berhasil dibangun dan dipasang pada vivo 1910 Android 12; pemeriksaan interaksi/izin tertahan karena layar perangkat terkunci. Manifest hasil build memuat izin lokasi serta foreground service bertipe location dari geolocator. Instalasi ini belum membuktikan pembacaan GPS, background tracking atau layar terkunci saat perjalanan.

Pemeriksaan lanjutan setelah pengguna membuka kunci: APK demo terakhir berhasil dipasang ulang dan Home terbuka, menampilkan Kurir Demo, 13 box pada 6 pesanan, serta tab Home/Riwayat/Performa/Profil. Tidak ditemukan FATAL EXCEPTION atau E/flutter pada potongan log yang diperiksa. Sistem vivo menolak injeksi sentuhan ADB dengan `INJECT_EVENTS`, sehingga klik, dialog izin, pembacaan posisi serta tracking background belum diverifikasi secara fisik. APK demo dan production terakhir berhasil dibangun. Skema deep link kedua flavor dipisahkan agar demo tidak menangkap tautan autentikasi production.

Validasi perangkat yang diperlukan sebelum operasional: bergerak di jalan, layar terkunci 10 menit, berpindah Maps/WhatsApp, izin dicabut, GPS dimatikan, sinyal lemah, dan kembali ke depot. Tes otomatis serta instalasi APK tidak membuktikan skenario perjalanan tersebut. Backend temuan audit sebelumnya tetap pekerjaan terpisah.
